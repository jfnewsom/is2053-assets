Key Concepts

.upper() and .strip() compose elegantly. input(prompt).strip().upper() reads from the user, removes any surrounding whitespace, and converts the result to uppercase, all in one expression. Wrapping that pattern in clean_input() means every input cleanup in the game looks the same. .isdigit() checks whether a string consists entirely of decimal digits, which is the right test for 'is this a non-negative whole number?' before calling int(). List of dictionaries is the third dictionary shape you've seen this module: a list whose items happen to be dicts. random.choice(hazards) returns one of those dicts, and hazard['name'] retrieves a field.

Step-by-Step Instructions

Number Input That Never Crashes
What You're Building

A rewrite of get_valid_int that checks the input with .isdigit() before converting it. Typing abc, 3.5, or nothing at all now gets a friendly error and a second chance instead of a crash.

Why This Matters

Tyler flagged this gap back in Lab 2.3, CP3: the original function caught out-of-range numbers but crashed on anything that was not a number. .isdigit() arrives with Chapter 8, so the gap closes now.

"I have been waiting on this one. Back in 2-3 we agreed the function caught out-of-range numbers but would faceplant on abc or an empty string. The fix is .isdigit() from Chapter 8. Two lines of logic and the function stops crashing."
Tyler Nguyen
Junior Developer, Bat City Collective
Step-by-Step Instructions
  1. In function_library.py, rewrite get_valid_int(prompt, min_val, max_val). Start with valid = False and value = 0, then loop while not valid:.
  2. Inside the loop, read and trim: user_input = input(prompt).strip().
  3. If user_input.isdigit(): convert with value = int(user_input). If it is in range, set valid = True; otherwise print your existing out-of-range message, unchanged: f'ERROR: Enter a number between {min_val} and {max_val}.' At this depth it runs past 79 characters, so split it the way Python allows adjacent f-strings: print(f'ERROR: Enter a number between ' on one line and f'{min_val} and {max_val}.') on the next.
  4. .isdigit() is False for negative numbers. Add elif user_input.startswith('-') and user_input[1:].isdigit(): and handle it the same way: convert, then range-check.
  5. Otherwise, print('ERROR: Please enter a valid whole number.').
  6. After the loop, return value. Update the docstring to say non-numeric input is rejected.

Symptom Where to Look
FileNotFoundError: hazards.txt Check CP2 (Hazards From a File). The data file must be in the same folder as lab-4-2.py. CodeGrade provides it as a fixture. If the files ARE in the folder and it still fails, you almost certainly opened the FILE in VS Code instead of the FOLDER. ValueError: invalid literal for int() at a menu prompt Check CP4 (Number Input That Never Crashes). The .isdigit() rewrite did not land in the library, or the wrong version of function_library.py is being used.
Yes/no prompt accepts y but rejects Y (or vice versa) Check CP5 (Clean Yes/No Answers). The rewrite uses clean_input, which uppercases its input, so the comparison should be against 'Y' and 'N' only.
