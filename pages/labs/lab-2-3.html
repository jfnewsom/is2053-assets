def get_valid_int(prompt, min_val, max_val):
    """
    Ask until the player types a whole number in a range.

    Args:
        prompt (str): The prompt to show
        min_val (int): The lowest number allowed
        max_val (int): The highest number allowed

    Returns:
        int: A whole number from min_val to max_val
    """
    value = 0
    valid = False
    while not valid:
        user_input = input(prompt).strip()
        if not user_input.isdigit():
            print('ERROR: Please enter a valid whole number.')
        else:
            value = int(user_input)
            if value < min_val or value > max_val:
                print(f'ERROR: Enter a number between '
                      f'{min_val} and {max_val}.')
            else:
                valid = True
    return value

value = 0 gives the variable a starting value, so return value always has one. The out-of-range message is Lab 2.1's, word for word; {min_val} and {max_val} fill in whatever range the caller asks for.

Why This Matters

Today, an answer like maybe quietly counts as no. get_yes_no() asks again instead. .strip().upper() cleans the answer and turns y into Y, so the function checks one letter instead of four. Then return answer == 'Y' hands back the comparison itself: True or False. Because the function returns a Boolean, the caller's if needs no comparison at all.

def get_yes_no(prompt):
    """
    Ask until the player answers y or n.

    Args:
        prompt (str): The prompt to show

    Returns:
        bool: True for yes, False for no
    """
    answer = input(prompt).strip().upper()
    while answer != 'Y' and answer != 'N':
        print("ERROR: Please enter 'y' or 'n'.")
        answer = input(prompt).strip().upper()
    return answer == 'Y'
