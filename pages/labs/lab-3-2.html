Destinations as Parallel Lists
← Back: CP1

One menu instead of two. Each city's destinations become two parallel lists, one of names and one of distances, and a single library function shows the menu for whichever city you're in.

Why This Matters

Right now the game has a block of print() lines for San Antonio and another for Houston. A list holds many values under one name, and destinations[0] is the first one. Parallel lists keep related values at the same position: SA_DESTINATIONS[1] is Houston, and SA_DISTANCES[1] is the 200 miles to it. A for loop over range(len(destinations)) visits every position once, so display_destinations() prints any city's menu, however many choices it has. It returns that number, so the prompt can say Choice (1-3): or Choice (1-2): by itself.

"Two menus that print the same way is one menu waiting to happen. Put the data in lists, write the printing once, and adding a city later means adding two lines of data, not another copy of the menu. That's the whole reason lists exist."
Danny Cavanaugh
Lead Developer, Bat City Collective

    """
    Return the destination lists for a city.

    Returns:
        tuple: The city's destinations and distances, as two lists

def display_destinations(city, destinations, distances):
    """
    Show the numbered destination menu for a city.

    Args:
        city (str): The city the player is in
        destinations (list): The cities you can travel to
        distances (list): The miles to each one, in the same order

    Returns:
        int: How many destinations the menu shows
    """
    print(f'From {city}, you can travel to:')
    for i in range(len(destinations)):
        print(f'  {i + 1}. {destinations[i]} - {distances[i]} miles')
    return len(destinations)

The gate without its long if/elif chains. Two library functions look up where you're going: one for HEADS, the choice you made, and one for TAILS, any other city on the menu.

Why This Matters

The menu number is a position in the list, counting from 1, and list positions count from 0, so choice 1 is destinations[0]. get_destination() does that subtraction once. For TAILS, get_redirect() builds two new lists without the city you wanted, then picks a random position in them. That replaces Lab 3.1's redirect and every branch under it, for San Antonio and Houston alike. The cities TAILS sends you to are the same as before.

def get_destination(destinations, distances, choice):
    """
    Look up the destination for a menu choice.

    Args:
        destinations (list): The cities on the menu
        distances (list): The miles to each one, in the same order
        choice (int): The menu number the player chose, from 1

    Returns:
        tuple: The destination and its distance
    """
    index = choice - 1
    return destinations[index], distances[index]


def get_redirect(destinations, distances, avoid):
    """
    Pick a random destination other than the one the player wanted.

    Args:
        destinations (list): The cities on the menu
        distances (list): The miles to each one, in the same order
        avoid (str): The destination the player wanted

    Returns:
        tuple: Another destination and its distance
    """
    cities = []
    miles = []
    for i in range(len(destinations)):
        if destinations[i] != avoid:
            cities.append(destinations[i])
            miles.append(distances[i])
    index = random.randint(0, len(cities) - 1)
    return cities[index], miles[index]

A save file that remembers the whole trip. After the nine values, savegame.txt lists the route, then a marker line, then the hazards. Loading reads them all back, and a damaged save file can't crash the game.

Why This Matters

A list can be any length, so the file can't say "line 10 is the route." A for loop writes one city per line, then a marker line, ---LISTS_END---, says where the route stops and the hazards start. Reading is the same in reverse: a while loop reads cities until it reaches the marker, and another reads hazards until readline() returns '', the end of the file. If a number line holds something int() can't read, Python raises ValueError; catching it with FileNotFoundError gives the player the same friendly message as a missing file.

def load_game():
    """
    Load the game from SAVE_FILE.

    Returns:
        tuple: The nine saved values, then the route and the hazards,
        in the order save_game() writes them, or None if there is no
        save file or it can't be read
    """
    try:
        infile = open(SAVE_FILE, 'r')
        player_name = infile.readline().rstrip('\n')
        current_city = infile.readline().rstrip('\n')
        total_miles = int(infile.readline().rstrip('\n'))
        total_turns = int(infile.readline().rstrip('\n'))
        total_hazards = int(infile.readline().rstrip('\n'))
        total_escaped = int(infile.readline().rstrip('\n'))
        games_played = int(infile.readline().rstrip('\n'))
        session_miles = int(infile.readline().rstrip('\n'))
        session_hazards = int(infile.readline().rstrip('\n'))

        # The route, up to the marker line
        visited_cities = []
        line = infile.readline().rstrip('\n')
        while line != '---LISTS_END---' and line != '':
            visited_cities.append(line)
            line = infile.readline().rstrip('\n')

        # The hazards, up to the end of the file
        hazards_list = []
        line = infile.readline().rstrip('\n')
        while line != '':
            hazards_list.append(line)
            line = infile.readline().rstrip('\n')

        infile.close()
        return (player_name, current_city, total_miles, total_turns,
                total_hazards, total_escaped, games_played,
                session_miles, session_hazards, visited_cities,
                hazards_list)
    except (FileNotFoundError, ValueError):
        return None
