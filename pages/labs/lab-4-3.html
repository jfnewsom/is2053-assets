Key Concepts

A set in Python is a collection of unique items with O(1) membership testing. my_set = set() creates an empty set. my_set.add(item) inserts an item (or does nothing if it's already present). len(my_set) gives the unique count. sorted(my_set) returns a new sorted list. Sets are unordered, so iterate them via sorted() for stable display. The trivia data shape introduced this lab is a dictionary keyed by city, with each value a list of dicts: trivia['Austin'] -> [{'question': '...', 'answer': 'TRUE'}, ...]. This combines two patterns from CP2 of Lab 4.1 (dict lookup) and CP2 of Lab 4.2 (list of dicts) into one structure.

Load the Trivia
What You're Building

load_trivia(filename) in the library: it reads trivia.txt into a dictionary of lists. Each city maps to a list of its questions, and each question is a dictionary with 'question' and 'answer' keys. Your game loads it at startup and reports how many questions it found across how many cities.

Why This Matters

Trivia is the foundation for the new Destination Gate in CP3. Grouping the questions by city in the loader means the gate can ask trivia['Austin'] and get Austin's questions immediately: parse once at startup, look up forever after.

"Look at the loaders side by side after this checkpoint: distances return nested dictionaries, city info returns a dictionary of dictionaries, hazards return a list of dictionaries, and trivia returns a dictionary of lists of dictionaries. Each one matches the access pattern the game needs. Pick the shape that makes the consumer code easiest to read."
Priya Venkatesh
Project Manager, Bat City Collective
Step-by-Step Instructions
  1. In function_library.py, add a section header comment block titled TRIVIA FUNCTIONS, above the test block at the bottom.
  2. Define load_trivia(filename) with a docstring. Create trivia = {} and open the file.
  3. For each line: parts = line.strip().split(','), then city = parts[0], question = parts[1], answer = parts[2].
  4. If city is not yet a key, set trivia[city] = []. Then trivia[city].append({'question': question, 'answer': answer}).
  5. Close the file and return trivia.
  6. In lab-4-3.py, add TRIVIA_FILE = 'trivia.txt' with your other file constants.
  7. In main(), right after the hazards load, add trivia = function_library.load_trivia(TRIVIA_FILE).
  8. Right after the trivia load, count the questions with an accumulator loop: total_questions = 0, then for city in trivia: add len(trivia[city]) to total_questions.
  9. After the Loaded ... possible hazards. line, print the count. The line is long, so split it into two adjacent f-strings inside one print(): print(f'Loaded {total_questions} trivia questions across ' and, on the next line, f'{len(trivia)} cities.').

What You're Building

"This is the heart of the new game feel. The player picks a destination, gets a question, and earns the next leg. Wrong answers are not a punishment; they are a detour, the same way get_redirect rerouted them on a TAILS flip in Module 3. Same mechanical outcome; entirely different feeling at the keyboard."
Sasha Mireles
Creative Director, Bat City Collective
Step-by-Step Instructions
  1. Add import random at the top of lab-4-3.py, with your other imports.
  2. Below the constants, define trivia_gate(dest, trivia, current, distances) with a docstring.
  3. Print the banner block exactly: print(), print('--- TRIVIA TIME! ---'), print(f'To reach {dest}, answer this question:'), print().

Sets: Unique Cities and Hazards
What You're Building

Two sets, unique_cities and unique_hazards, filled during play, and sorted() to turn them into the trip report's lists. The hazard section now lists each hazard once, under the title HAZARDS ENCOUNTERED (Unique, A-Z). The Lab 4.2 uniqueness loop and the .copy()/.sort() pattern retire.

Why This Matters

A set keeps each value once, automatically. Adding a city you already visited, or a hazard you already faced, changes nothing. That replaces about eight lines of bookkeeping with two.

"Notice we are building each set from its list, not from set(). On a fresh game the visited list is just ['San Antonio']. On a resumed game, the loaded list might hold several cities, and the set rebuilds with all of them. Both cases handled with one line. That is why set(iterable) exists."
Priya Venkatesh
Project Manager, Bat City Collective

  2. Everywhere you append to visited_cities, add unique_cities.add(current_city) on the next line. There are two places: arrival at a destination, and the dead-end return to San Antonio.
  3. In the hazard block, right after hazards_list.append(name), add unique_hazards.add(name).
  4. In the trip report block, delete all of the Lab 4.2 bookkeeping: the two sorted_hazards lines (.copy() and .sort()), the unique_cities = [] line, the for city in visited_cities: loop with its if city not in unique_cities: check, and the comments above them.
