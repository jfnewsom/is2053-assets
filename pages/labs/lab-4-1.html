Key Concepts

Two new tools arrive together. .strip().split(',') is the standard CSV-parsing pattern from Chapter 8: .strip() removes the newline at the end of each line, .split(',') breaks the comma-separated values into a list of fields. Dictionaries (Chapter 9) replace parallel lists for any data shape where the keys are meaningful. A nested dictionary is just a dictionary whose values are themselves dictionaries: distances['San Antonio'] is itself a dictionary mapping destinations to miles. The in operator works on dictionaries too. 'Houston' in distances checks if Houston is a key. This is how the loader builds the nested structure: it checks if city1 not in distances: before creating the inner dictionary.

How the Road Network Is Modeled

The 24 routes in city_distances.txt are the cities you can drive between on a Texas interstate. San Antonio reaches Houston (I-10), Austin (I-35), Laredo (I-35), El Paso (I-10), and Corpus Christi (I-37). Houston reaches Galveston (I-45) and Dallas (I-45). Step-by-Step Instructions
  1. Open function_library.py. Below your existing functions, but ABOVE the test main() and the if __name__ == '__main__': block at the very bottom, add a section header comment block titled CITY DATA LOADERS.
  2. Under it, define load_city_distances(filename) with a docstring describing what it returns.
  3. Inside the function, create an empty dictionary: distances = {}. Open the file with infile = open(filename, 'r').
  4. Loop with for line in infile:. For each line, parts = line.strip().split(','), then city1 = parts[0], city2 = parts[1], miles = int(parts[2]). Only the distance needs int().
  5. If city1 is not yet a key, set distances[city1] = {}. Then set distances[city1][city2] = miles.
  6. After the loop, infile.close() and return distances.
  7. In lab-4-1.py, add the constant DISTANCES_FILE = 'city_distances.txt' with your other constants.
  8. In main(), right after the welcome banner and its print(), add: print('Loading city data...'), then distances = function_library.load_city_distances(DISTANCES_FILE), then print(f'Loaded {len(distances)} cities with travel routes.'), then print().
  9. Heads-up: your Lab 3.3 in-game loop also uses the name distances, for the list that get_city_data() returns. That is harmless for now, since nothing reads the dictionary after startup yet. CP4 removes that line.

Tips & Pitfalls
Forgetting .strip() Each line ends with a newline character. Without .strip(), the last field keeps it. Here the last field is the distance, which int() forgives, but in CP3 the last field is the tagline, and the hidden newline breaks every line that prints it. Use .strip() in both loaders.
Casting parts[0] or parts[1] to int Only the distance is a number. City names are strings.
Skipping the if city1 not in distances: guard The first time you see a city, distances[city1] does not exist yet, so distances[city1][city2] = miles raises KeyError.
Putting the function below the if __name__ block Keep every library function above the test block at the bottom, where the others live. That block is only for running the library on its own.
Using with open(...) That works too (Chapter 6 covers it), but these steps use open() and close(), so match them to keep your code aligned with later labs.

Step-by-Step Instructions

If Something Breaks

Common failure patterns and where they came from:

Symptom Where to Look
KeyError at startup, inside load_city_distances Check CP2 (Load City Distances): the loader is not inserting 'San Antonio' as a top-level key. Verify the if city1 not in distances: guard.
FileNotFoundError: city_distances.txt Check CP1. The data files must be in the same folder as lab-4-1.py when you run it locally. CodeGrade provides them as fixtures. If the files ARE in the folder and it still fails, you almost certainly opened the FILE in VS Code instead of the FOLDER. Python then looks for the data files wherever VS Code was launched from, not next to your code. Use File → Open Folder and pick the lab folder itself; you should see the .txt files listed in the sidebar. Also keep them as plain .txt data files. Do not re-save them as .py.
Menu shows distances but the wrong destinations (Houston instead of Corpus Christi, etc.) Check CP4 (Menus From the Dictionary). Verify display_destinations iterates distances[city] in order and prints both the destination key and the value.
Dead-end prompt fires at the wrong cities (or never fires) Check CP5 (is_dead_end). Both 'DEAD_END' and 'WRONG_WAY' count as dead ends. Compare exact uppercase strings.
Trip report does not appear at the end of the game The trip report runs after the in-game loop exits naturally. If the player saves and quits, the report is intentionally skipped (that's the save path, not the report path).
ValueError: invalid literal for int() when loading distances Check CP2. After parts = line.strip().split(','), only parts[2] gets cast to int. parts[0] and parts[1] stay as strings.
