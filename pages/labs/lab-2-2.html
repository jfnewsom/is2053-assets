Testing Pins

A pin swaps a random line for a fixed value, so a test comes out the same every time. Comment out the line in the second column and put the line from the third column right under it, at the same indent. When a test needs a different value (like roll = 5), it says so. To restore a pin, delete the fixed line and take the # off the original. A pin stays in your file until a step changes it or says to restore it, so pins from earlier checkpoints may still be there. A pin a test doesn't mention can stay as it is: with the roll at 20, every leg takes one turn and the hazard lines never run. A value in parentheses in the last column is the one that checkpoint uses.

def flip_coin():
    """
    Flip a coin and return the result.

    Returns:

    result = random.randint(1, 2)

This main() belongs to the library, not to your game. Because of the if __name__ guard, it runs only when you run function_library.py itself, never when lab-2-2.py imports it. Every function in the library gets a docstring, the same as main() in your lab.

Two more functions: roll_d20(), which rolls a 20-sided die, and check_percentage(), which says yes a certain percent of the time. Together with flip_coin(), that's every random thing your game needs.

Why This Matters

check_percentage() takes a parameter: the percent you pass in when you call it. check_percentage(30) is true about 30 times out of 100. One function, any chance you want, and the game never needs to know how the dice work.

Step-by-Step Instructions
  1. Between import random and the RANDOM FUNCTIONS banner, add the die's limits as constants, with two empty lines above and below:
# ============================================================
# CONSTANTS
# ============================================================
D20_MIN = 1
D20_MAX = 20
  1. Under flip_coin(), with two empty lines between them, add roll_d20():
def roll_d20():
    """
    Roll a 20-sided die.

    Returns:
        int: Random number from 1 to 20
    """
    return random.randint(D20_MIN, D20_MAX)
  1. Under roll_d20(), the same way, add check_percentage(). It rolls 1 to 100 and returns True when the roll is at or under the percent:
def check_percentage(percent):
    """
    Return True a certain percentage of the time.

    Args:
        percent (int): The percentage chance (0-100)

    Returns:
        bool: True if the roll is within the percentage
    """
    roll = random.randint(1, 100)
    return roll <= percent
  1. In the self-test main(), add these two lines between the flip_coin() line and the Library loaded line:
    print(f'  roll_d20() => {roll_d20()}')
    print(f'  check_percentage(50) => {check_percentage(50)}')

No more typing your roll. lab-2-2.py imports your library and calls roll_d20() every turn. To test, you'll pin the roll to a fixed number.

Why This Matters

Random code is hard to test: every run is different, so you can't compare it to an expected output. A pin fixes that. You comment out the random line and put a fixed value right below it, so the program does the same thing every time. When you're done testing, you put the real line back. CodeGrade does its own version of this with fixed dice, and it tests every outcome.

"Here's the hole from Lab 1.3, closed for good: nobody types a 30 anymore. And here's my favorite testing trick, which you'll use the rest of the semester. Pin the dice. Run the case you want, on purpose, as many times as you want. A tester who waits for luck to show them the bug is going to wait a long time."
Terrence "T-Bone" Booker
QA Lead, Bat City Collective
